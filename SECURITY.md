# Security Policy

The TraceNest team takes the security and privacy of our users, reporters, and community subscribers seriously.

---

## Supported Versions

Security updates and patches are actively applied to the following branch:

| Version / Branch | Supported          |
| ---------------- | ------------------ |
| `main`           | :white_check_mark: |

---

## Reporting a Vulnerability

If you discover a security vulnerability within TraceNest, please **do not** open a public issue.

Instead, please report security concerns via one of the following channels:
1. **GitHub Security Advisory**: Use the "Report a vulnerability" button under the **Security** tab of the GitHub repository.
2. **Direct Email**: Contact the core maintainers privately at `security@tracenest.app` (or the project administrator).

Please include the following details in your report:
- Type of vulnerability (e.g., SQL injection, authentication bypass, CSRF, sensitive data exposure).
- Full steps to reproduce or proof-of-concept (POC) exploit code/payload.
- Impact of the issue and potential mitigations if known.
- Any relevant logs, screenshots, or network traces.

---

## Disclosure Policy

- We will acknowledge receipt of your report within 48 hours.
- We will work diligently to validate, reproduce, and patch the reported issue.
- Once fixed, a security release will be deployed and an advisory published crediting the reporter (unless anonymity is requested).
